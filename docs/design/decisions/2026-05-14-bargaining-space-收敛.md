### 关键事实核实

读 `scripts/battle/blind_clash_scene.gd:118-123` — `_open_boss_deck()` 实际把 `boss.deck + boss.hand + boss.discard_pile` **全 25 张合并展示**给玩家：

```gdscript
func _open_boss_deck() -> void:
    var all_boss: Array[CardData] = []
    all_boss.append_array(battle.boss.deck)
    all_boss.append_array(battle.boss.hand)
    all_boss.append_array(battle.boss.discard_pile)
    boss_deck_view.show_boss_deck(all_boss)
```

→ **Boss 牌库已经全透明**（按 `B` 键），但玩家感觉没用，因为它呈现为**静态字典**——不分"已打/未打/在手"，不带时间线，不带剩余分布饼图。

→ 真正问题是：**信息已经在那儿了，但没被组织成"决策工具"。**

## 2. 三方观点综述

### 2.1 Creative Director（基于 Pillars 的方向裁决）

> Pillar 1（Calculated Aggression）+ Pillar 4（Readable Complexity）当前都没兑现。

- **推荐**：方向 A —— 把玩家牌库**砍到 6-8 张**（"人格牌组"），LLM Boss 在小池子里负责语气/节奏/心理战
- **拒绝**：方向 B 全透明（"LLM 退化为牌库说明书的执行器"）
- **设计验收**：让玩家在 Boss 1 第 3 回合**口述决策思路**——能说出"因为弃堆有 X、他刚说了 Y、所以我赌 Z"才算成功

> 引用："牌少 → LLM 的语气、节奏、心理战反而变成主菜，不再被组合爆炸稀释。"

### 2.2 Game Designer（具体牌库结构方案）

提出 3 套方案，**推荐方案 A**：

| 维度 | 方案 A 开放牌库 | 方案 B 渐进披露 | 方案 C 战前公示 |
|---|---|---|---|
| 玩家/Boss 牌库 | 20/20 对等 | 20/25 维持 | 20/20 |
| Boss 弃堆 | ✅ 完全可见 | ⚠️ 滚动 3 回合 | ❌ 战中暗 |
| 工程量 | S+L+M+M | M+XL+L+L | S+M+S+S |
| 推理可行性 | 贝叶斯更新 ⭐⭐⭐⭐⭐ | 受限 ⭐⭐⭐ | 仅先验 ⭐⭐ |

> 引用："24 抽 / 20 张 ≈ 见全副，第 4-5 回合起贝叶斯推理产生稳定收益。"

**最大风险标记**：Boss 失去神秘感。**缓解**：保留 2 张"协议牌"暗置（构成公示但具体内容遮蔽）。

### 2.3 UX Lead（信息架构改造）

**关键判断**：当前所有信息都已经透明，**真正缺的是把信息变成决策工具的 UI 元件**。

提出 4 圈层信息分层 + 3 个 P0 元件：

| 元件 | 形态 | 位置 |
|---|---|---|
| **A：Boss 出牌时间轴** | 横条胶囊，每张牌 = 24×24px 类型色块（红/蓝/橙），按时序排列 | 屏幕正上居中、Boss 血条下 |
| **B：剩余牌库三色饼图** | 80px 环形图，中心"剩 12" | B 浮层右上 + 缩小版嵌入 HUD |
| **C：克制三角速查贴片** | 120×120px 三角箭头，悬停手牌时浮现 | 左下角 |

**红线**（绝不做）：
1. 不要显示 Boss 手牌内容
2. 不要给"建议出牌"高亮
3. 不要把所有元件常驻

## 3. vibe-lead 综合判断

### 3.1 三方分歧解析

| 议题 | CD | GD | UX | 调和 |
|---|---|---|---|---|
| 牌库大小 | 砍到 6-8 | 保留 20 | 不评论 | 长期可砍，但**短期不是瓶颈** |
| 信息透明度 | 抗拒（怕失神秘感） | 拥抱（贝叶斯推理） | 已经透明（事实如此） | UX 占优——事实已成 |
| LLM Boss 角色 | 担心花瓶 | 不担心 | 不影响 | 牌少/信透≠LLM 花瓶；玩家手牌仍暗 |

### 3.2 锐利结论

- **创意总监的担忧基于错误事实**（以为 Boss 牌库还是黑箱）
- **游戏策划的方案 A** 与 **UX 主管的 P0** 本质是**同一件事**：把已透明的信息武器化
- **真正的 sprint 0 改动 = UX P0 那 3 个元件**，工程量 1-2 天
- **创意总监的"砍牌库"是更长期的方向**，不必现在拍板

## 4. 决策建议（呈给用户）

### 选项 A1（推荐 ⭐）：先做信息武器化（1-2 天）
- 落地 UX P0：Boss 时间轴 + 剩余饼图 + 重构 B 键浮层
- 把"已经在那儿但用不上的信息"组织成决策工具
- 预期：玩家在 Boss 1 第 3 回合开始能做条件概率推理
- **2 周后回看**：如果博弈深度仍不够，再考虑 A2

### 选项 A2：激进路线 — 砍牌库到 8 张（2-4 周）
- 玩家牌库 20 → 8（人格牌组），Boss 同步缩到 8
- 创意总监推荐路线，最锋利但工程量最大
- 风险：构筑深度被压缩，Roguelike 留存压力
- **建议**：仅在 A1 验证不够时才走

### 选项 A3：折中 — A1 + 部分 A2（1 周）
- 做 A1 全部内容
- 再加：把玩家手牌上限从 7 → 5，逼迫每张牌都被记住
- 不动牌库总数

### 共同附加项（无论选哪条）
- **B-1**：保留 Boss 2 张"协议牌"暗置 → 守住 Boss 神秘感
- **B-2**：玩家弃牌堆/抽牌堆入口图标化（左下角，不再藏在文字 hint）
- **B-3**：每回合结算后 2.5s Toast（"Boss 出 X → 你出 Y → 克制成功"）
