## 0. TL;DR

把 v0.3 ~ v0.6 的 **「双盲暗出 4 张 → 翻盅」** 改成：

> **双方各抽 4 张候选 → 全程明牌 → 轮流先手（首回合随机） → 按出牌位 1 → 4 交替 Pick → 4 对填满后一次性翻盅同时结算**。

体验从 **双盲心理战**（信息为零、押宝直觉）→ **顺序博弈 + 局部信息博弈**（信息透明，但 Pick 顺序与槽位绑定造成结构性不对称）。

**开盅戏剧性通过延迟结算保留** —— Pick 完所有 4 对前不计算任何伤害；翻盅瞬间一次性爆发飘字、震屏、克制连锁、☯ 2:2 平衡 ×2.0。

## 1. 设计哲学转变 / Design Philosophy Shift

### 1.1 旧循环（GDD-04 §1, §5）的实战痛点

| 问题 | 表现 |
|---|---|
| **认知盲区过大** | 玩家暗出后无任何对方信息，决策退化为押宝；新手挫败感高 |
| **0 费绑定不可视** | 0 费牌在暗出阶段不显形，玩家无法围绕它做策略 |
| **手牌缩略条 UX 割裂** | v0.6.1 屏蔽部署阶段后，缩略条不显示成为既成事实（D4 已确认非 bug，但暴露旧循环对手牌可视化的依赖） |
| **LLM Boss 黑箱** | Boss 一次性输出 4 张暗出 + 顺序，玩家无法从交互中读出对手意图，AI 的"博弈感"无法被感知 |

### 1.2 方案 B' 的目标美学（MDA-Aesthetics）

| 优先级 | 美学 | 如何实现 |
|---|---|---|
| **P0 Challenge** | 顺序博弈下的策略深度 | 先手方 Slot 1 暴露 1 张但占位，后手方信息更全但选择空间被压缩；交替到 Slot 4 |
| **P0 Expression** | 玩家的 Pick 顺序本身是表达 | 把强牌放 Slot 1 威慑 vs. 藏 Slot 4 反制；把火放 Slot 2 诱 Boss Slot 3 出木 |
| **P1 Sensation** | 翻盅瞬间的张力 | 4 对全部 Pick 完毕后才结算，飘字/震屏/克制连锁一次性爆发 |
| **P1 Discovery** | 读对方习惯 | LLM Boss 的 Pick 偏好在 8 步交互中暴露给玩家，形成可学习的对手画像 |

### 1.3 SDT 验证

- **Autonomy**：每次 Pick 都是有意义的二维选择（候选 × 槽位），无假选择
- **Competence**：明牌让玩家可以**推理**胜负，胜负原因可读（解决 v0.4.3 死因——"信息不对称导致博弈感丢失"）
- **Relatedness**：LLM Boss 的 Pick 顺序成为可观察的"性格特征"，强化对手的人格感

### 1.4 嵌套循环重映射

| 循环层 | GDD-04 旧 | GDD-07 新 |
|---|---|---|
| 30s 微循环 | 暗出 1 张（4 张选择一次性塞入） | **Pick 1 张到指定槽位**（决策点 8×/回合 vs. 旧 1×） |
| 5-15min 中循环 | 1 BP 回合 = 暗出 4 + 翻盅 | 1 BP 回合 = 8 次 Pick + 1 次翻盅 |
| 会话宏循环 | 关卡/Boss 进度 | **不变** |

## 3. Pick 阶段详细规则 / Pick Phase Rules

### 3.1 Pick 操作的两个维度

每次 Pick 是 **(候选, 槽位)** 二元组：

| 维度 | 取值范围 | 约束 |
|---|---|---|
| **候选** | 玩家自己 4 张候选中任意一张 | 必须满足能量约束（剩余能量 ≥ card.cost） |
| **槽位** | 当前激活的 Slot（1→4 顺序） | 同一 Slot 当前先手已 Pick 的话，后手只能 Pick 同 Slot；轮转推进由系统控制，不允许跳过 |

### 3.2 Pick 阶段玩家可见信息（明牌全开）

- ✅ 自己的 4 张候选（元素/光暗/费用/效果数值）
- ✅ Boss 的 4 张候选（同上 —— 推荐 Q-BP-1 = 完全可见）
- ✅ 双方剩余能量
- ✅ 双方已 Pick 进出牌位的所有牌（含 Slot 号）
- ✅ 当前轮到谁 + 当前 Slot 号（UI 高亮）
- ✅ 实时预测条："光X 暗Y → 距离平衡 N 张"（沿用 GDD-06 Sprint B 设计）
- ❌ 对方接下来 Pick 哪张（这是博弈的唯一信息差来源）

### 3.3 能量扣除与校验

- 玩家/Boss 初始能量 = 8（v0.7.0-alpha-pick.3 调整：4 槽 × cost 1~2 平均下能稳定填满 4 槽 + 留博弈空间）
- 每次 Pick 瞬间扣除 `card.cost`
- 候选区中**剩余能量买不起的候选**会灰显（视觉提示），点击给出"能量不足"toast
- Pick 完所有 4 个 Slot 后能量未必清零（多余能量本回合作废）

### 3.4 0 费牌的处理（Q-BP-4）

详见 §7 Open Questions。推荐方案：**0 费牌作为独立"修饰格"附在主 Slot 下方**，与主牌同时翻盅、共享倍率。

### 3.5 Pick 阶段不可逆性

- 已 Pick 的 (候选, 槽位) 不可撤回（保持博弈节奏）
- 但允许"准备状态" UI：玩家选中候选后预览到目标槽位，**点击确认**后才真正提交（防误触）

### 3.6 流程不允许的操作

| 不允许 | 处理 |
|---|---|
| 跳过自己当前的 Pick | 强制 Pick（即使全候选都买不起 → 强制 Pick 一张 0 费占位 / 见 §7 Q-BP-4） |
| 一次 Pick 两张到同一槽位 | UI 不允许 |
| Pick 到非当前激活槽位 | UI 不允许（Slot 1 未填满前 Slot 2 不激活） |

## 4. 同时翻盅与结算 / Simultaneous Reveal & Resolve

### 4.1 与 GDD-04/06 的兼容

| 规则 | 来源 | 在 GDD-07 的状态 |
|---|---|---|
| 三角克制 → 火水木 3-cycle | GDD-06 §2 | ✅ 完全沿用 |
| ×0.5 / ×1.5 倍率 | GDD-06 §2.2 | ✅ 完全沿用 |
| 2:2 平衡 ×2.0（仅玩家方） | GDD-06 §3.2 | ✅ 完全沿用 |
| 0 费绑定共享倍率 | GDD-04 §2.5 | ✅ 沿用（落点改为"修饰格"，§7 Q-BP-4） |
| 多余牌 100% 直接生效 | GDD-04 §2.4 | ⚠️ **作废**（B' 方案 4 槽位都填满，不存在多余牌） |
| 逐对翻开 | GDD-04 §1 Phase 4 | ❌ **取代**为同时翻盅 |

### 4.2 结算粒度变化

| 项 | 旧（GDD-04） | 新（GDD-07） |
|---|---|---|
| `clash_resolver.resolve_clash()` 入参 | `(player_4_blind_cards, boss_4_blind_cards)` 两个 Array[CardData] | `(picked_pairs: Array[Pair])` 4 个 (player_card, boss_card) 元组 |
| 结算次数 | 每 Slot 翻一次结算一次 + 总收尾 | 4 对一次性结算 + 1 次总飘字汇总 |
| 飘字时机 | 每 Slot 翻牌后立即 | 4 对全翻盅后统一播放（克制连锁感） |

**实施提示**：`clash_resolver.gd` 的核心数学函数（克制判定、倍率计算、平衡检测）**100% 复用**，只改外层调度循环。这是 D3 决策的成本节省核心来源。

### 4.3 翻盅演出

- 4 对牌**同时**从牌背翻向牌面（0.5s 动画）
- 翻面后克制对从 Slot 1 到 Slot 4 **依次**触发飘字（每个间隔 0.3s，制造连锁感）
- 若触发 ☯ 2:2 平衡，全部克制对的飘字升级为 `×2.0`，伴随金白闪光
- 总演出时长 ~2.5s

## 5. LLM Boss 决策接口重设计 / LLM Boss Re-Architecture

### 5.1 旧接口（ADR-001）

```
boss_ai.warm_up()                              # DEPLOY 阶段预热
await boss_ai.select_blind_cards_async()       # BLIND 阶段一次返回 4 张+顺序
```

**问题**：B' 流程下 Boss 需要在每个 Slot 实时决策，且要看到玩家已 Pick 的牌；一次性 4 张决策无法适配。

### 5.2 新接口（推荐 = 4 次轻量调用 + 缓存）

```gdscript
# 每次 Slot 轮到 Boss 时调用一次
await boss_ai.pick_for_slot_async(
    slot_index: int,                # 1~4
    boss_candidates: Array[CardData],
    player_candidates: Array[CardData],   # 明牌可见
    picked_state: Array[Pair],            # 已填充的 (player_card, boss_card)
    is_first_picker: bool,
    boss_remaining_energy: int,
) -> CardData                              # 返回 Boss 选哪张候选
```

### 5.3 调用次数 vs Token 预算

| 方案 | LLM 调用次数/回合 | 单次 Token | 总 Token | 延迟（DeepSeek） | 评估 |
|---|---|---|---|---|---|
| **A：一次性 4 步序列** | 1 | ~800 in / ~150 out | ~950 | 1.5-2.5s | ❌ 无法看到玩家中途 Pick，博弈感差 |
| **B：4 次轻量调用** | 4 | ~500 in / ~50 out | ~2200 | 4×0.8s ≈ 3.2s（顺序）/ 0.8s（用预热） | ⚠️ 总 Token 翻倍但可接受 |
| **C：B + 预热 Slot 1** | 4，但 Slot 1 预热 | 同上 | 同上 | Slot 1 = 0s（预热命中）/ 后续 0.8s | ✅ **推荐** |

**推荐方案 C**：
- Phase 0 抽完牌后立刻 `warm_up_pick_slot_1_async()`（玩家在看候选选 Slot 1 时 Boss Slot 1 已在算）
- Slot 2-4 在玩家 Pick 完时触发，期间 1.5s `BossThinkingOverlay` 演出（沿用 ADR-001 §6）
- **每场战斗 LLM 成本约 ¥0.04-0.10**（vs 旧 ¥0.01-0.04，3 倍涨幅但仍可接受）

### 5.4 Prompt 结构变化

旧 BLIND prompt：
```
你是 Boss "回响"。从手牌选 4 张暗出，给出顺序。
[手牌列表]
```

新 BP prompt（每个 Slot 一次）：
```
你是 Boss "回响"。当前 Slot {N}，{是先手|你已看到玩家 Slot {N} Pick 了什么}。
你的候选（4 张明牌）：[...]
玩家候选（4 张明牌）：[...]
已填充槽位：[...]
你剩余能量：{X}
请选择候选中的一张，并简要说明意图（用于演出字幕）。
```

### 5.5 Fallback 兼容性

ADR-001 §5 错误恢复矩阵全部保留：
- 网络超时 → 切规则 AI（rule_blind_clash_ai.gd 需要新增 `pick_for_slot()` 实现）
- JSON 非法 → retry 1 次 → fallback
- **新增**：连续 3 次 fallback 后整场切规则 AI

### 6.2 翻盅阶段视觉切换

- Pick 阶段结束 → 候选区淡出 → 出牌位放大居中（占满屏幕中央 70%）

- Slot 1→4 依次飘字（克制 ×1.5 / ×2.0 / 平衡 ☯）
- 飘字结束 → HP 条更新动画 → 进入下一回合

### 6.3 先手宣告演出（v0.8.0-locked.1：随机 → 轮流）

- Phase 1 触发时屏幕顶部下落一个横幅
- 横幅主标题：**"先手：你"** / **"先手：回响"**
- 横幅副标题（按回合区分）：
  - **R1**："首回合：随机决定先手"
  - **R≥2**："轮流先手 · 第 N 回合换手"
- 总时长 2.0s（淡入 0.3s + 停留 1.4s + 淡出 0.3s），战斗日志同步打 `首回合先手（随机）` 或 `轮流先手` 前缀

## 7. 5 个 Open Questions 推荐答案 / Q-BP-* Recommendations

> 每条给出推荐方案 + 理由，让用户能直接拍板（yes / 选其他选项 / 建议修改）。

### Q-BP-1：候选互见性

| 选项 | 优点 | 缺点 |
|---|---|---|
| **(a) 完全可见**（玩家看 Boss 4 张明牌+全数值） | 最大化信息透明度 → 最大化推理空间 → 与"明牌博弈"主张一致 | 博弈深度依赖 Pick 顺序，不依赖信息差 |
| (b) 半明（只看对方已 Pick 进出牌位的部分） | 保留部分信息差 | 退化成"暗出 4 张但每 Slot 翻一对"= 旧 GDD-04 微调，不是真正方案 B' |
| (c) 玩家看 Boss 4 张但只看类型不看数值 | 中庸 | UX 复杂，玩家学习成本高 |

🎯 **推荐 (a) 完全可见**：方案 B' 的核心价值就是"明牌博弈"。半明会让 B' 退化为 B 方案，丢失 B' 相对 B 的最大差异化。**用户拍板时如果觉得"信息差太少不够刺激"，回退到 (c) 而非 (b)**。

### Q-BP-2：先手补偿

| 选项 | 优点 | 缺点 |
|---|---|---|
| **(c) 不补偿**（Slot 1 占位 = 占便宜，先手暴露 = 吃亏，自然平衡） | 实施 0 成本；交替 Pick 本身就是补偿（先手 4 次先 Pick + 4 次后看局面 = 平衡） | 数据未验证 |
| (a) 先手方多 1 张候选（5 选 4） | 直观补偿 | 候选区 UI 要适配可变数量 |
| (b) 先手方 +1 能量 | 补偿明显 | 改变能量经济模型，数值平衡要重做 |

🎯 **推荐 (c) 不补偿**：先手方在 Slot 1 占位上有先发威慑（强迫后手反应），后手方在 Slot 4 上信息最全，**结构性自平衡**。如果实战测试显示先手胜率 >55%，再追加 (a)。

---

### Q-BP-3：候选回合内固定 vs 补抽

| 选项 | 优点 | 缺点 |
|---|---|---|
| **(a) 回合内固定 4 张，每对结算后不补抽** | 简单直观；Pick 决策粒度 = 4 选 1 → 4 选 1 → 4 选 1 → 4 选 1，策略稳定 | 候选若全是同元素，玩家被锁死 |
| (b) 每对结算后从牌库补 1 张到候选 | 牌库切片更动态 | 会让 Pick 决策有"等好牌"的拖延，与同时翻盅冲突 |
| (c) 4 张候选维持 4 张但允许 mulligan | 救场机制 | UX 复杂 |

🎯 **推荐 (a) 回合内固定**：与"同时翻盅"决策（D3）哲学一致 —— 整个回合是一个完整的 4 维决策。回合末弃 4 张候选（已 Pick 的进弃牌堆，未 Pick 的进弃牌堆 / 也可以保留 1 张到下回合作为机制扩展点，但 v0.7.0-alpha 先简单全弃）。

---

### Q-BP-4：0 费牌如何融入 BP

> 旧 GDD-04 §6.4：0 费牌不独立参与碰撞，绑定到一张主牌上叠加效果。

| 选项 | 优点 | 缺点 |
|---|---|---|
| **(a) 0 费作为"修饰格"附在主 Slot 下方** | 视觉清晰；明牌时玩家可看到 Boss 的 0 费修饰；继承 GDD-04 §2.5 倍率共享 | UI 要加修饰格；候选 4 张可能有 2 张 0 费导致占用太多修饰位 |
| (b) 0 费在 Pick 时作为"附加选择"（先 Pick 主牌再 Pick 0 费） | 决策更灵活 | UX 流程复杂，从"4 选 1"变成"4 选 1+1" |
| (c) v0.7.0-alpha 阶段不出 0 费牌（暂时移除） | 简化实施 | 牌库少一类策略 |
| (d) 0 费独立占用一个 Slot | 简单 | 改变核心 4 槽位逻辑 |

🎯 **推荐 (c) v0.7.0-alpha 暂时移除 0 费**：当前 GDD-06 牌库 10 张全是 1-2 费，没有 0 费牌。**0 费是 v0.7.0+ 扩展点**，待 BP 方案 B' 流程稳定再讨论。这样 v0.7.0-alpha 直接砍掉 0 费复杂度。

> 如果用户坚持 v0.7.0-alpha 就要 0 费，回退到 (a)。

### Q-BP-5：陷阱阶段长期回归 vs 永久砍

| 选项 | 优点 | 缺点 |
|---|---|---|
| **(b) BP 稳定后回归（v0.8.0+）** | 保留陷阱+认知探针的策略深度；先把核心 BP 跑通再加复杂度 | 玩家短期看不到陷阱机制 |
| (a) 永久砍（GDD-04 §3 / §4 永久作废） | 极简；focus 在 BP 上 | 牺牲长期博弈深度 |
| (c) v0.7.0-alpha 就保留陷阱（与 BP 并存） | 保留全部机制 | 复杂度爆炸；BP+陷阱+认知探针三层叠加，实施风险高 |

🎯 **推荐 (b) BP 稳定后回归**：v0.7.0-alpha → v0.7.0-beta → 玩家实战测试通过 → v0.8.0 重启陷阱（GDD-04 §3）+ 认知探针（GDD-04 §4 / GDD-05）。陷阱在 BP 框架下的接入方式届时再设计（很可能改成"Pick 阶段前部署到出牌位的反应槽位"）。
