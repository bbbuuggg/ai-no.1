# Design Pillars & 核心循环 GDD

> 项目：NULL Protocol（暂定名）
> 引擎：Godot 4.6.2 | 视角：2.5D | 类型：Roguelike Boss Rush 卡牌
> 版本：v0.1 | 日期：2026-04-30

---

## Part 1: Design Pillars

### Pillar 1: Calculated Aggression（克制的攻势）

**定义**：玩家是入侵者，每一步都是主动选择——但资源有限，逼迫精密计算而非蛮力堆叠。

**体现**：
- 约束令是一次性消耗品，用了就没了。玩家必须在"现在用掉保命"和"留到后面对付更强Boss"之间抉择
- 行动牌没有无限循环的无脑combo，每张牌的能量成本让你必须取舍
- 40分钟单局意味着每个决策的权重很高，不存在"反正再来一把"的廉价感

**反面案例**：如果违反——变成无脑刷牌、无限资源的爽游，Boss变成血袋，玩家不需要思考出牌顺序。像一个没有能量上限的杀戮尖塔，每回合打出所有牌。

---

### Pillar 2: Asymmetric Duel（不对称对决）

**定义**：玩家与Boss的战斗不是镜像对称的规则——你是黑客，用约束和巧计；它是AI，用压倒性的算力和模式。

**体现**：
- Boss不打牌、不抽牌，它有自己的行为状态机和攻击模式
- 约束令是玩家独有的"破规则"工具——封印Boss某个行为，让对决规则暂时向你倾斜
- Boss的全息几何体形态变化就是它的"意图"提示，玩家需要读取模式而非猜测

**反面案例**：如果违反——Boss也打牌、也有手牌，变成两个人打牌的镜像对称TCG。失去"人vs机器"的叙事张力和赛博朋克的调控师幻想。

---

### Pillar 3: Escalating Commitment（递进的承诺）

**定义**：每过一层，你既更强也更脆弱——行动牌变强了，但安全网（约束令）在减少。越深入越骑虎难下。

**体现**：
- 7层结构中约束令逐层减少（从"有保险"到"裸奔"）
- 行动牌通过层间奖励逐步增强，补偿约束令的减少
- Roguelike的永久死亡：一旦失败从头再来，前几层的投入全部归零
- 这形成一个天然的情绪弧：安全→紧张→窒息→突破

**反面案例**：如果违反——每层难度平坦，资源均匀分配，后期和前期手感一样。没有越来越深入"深井"的压迫感，变成7个独立的小关卡。

---

### Pillar 4: Readable Complexity（可读的复杂度）

**定义**：系统交互可以深，但每个单一要素必须一眼看懂。复杂度来自组合，不来自单个规则的晦涩。

**体现**：
- 每张牌的效果用一句话说清
- Boss的下一步行动有明确的视觉预告（几何体形态变化）
- 约束令效果简单直接："封印Boss的[某行为]1回合"
- 2.5D呈现：3D牌桌提供氛围，2D卡牌UI保证信息清晰度

**反面案例**：如果违反——牌面写满小字、需要查wiki才知道效果、Boss行为完全不可预测。变成记忆力考试而非策略博弈。

## Part 2: 核心循环 GDD

### 1. 游戏概述

玩家代号NULL，前调控师，闯入"深井"——枢网的逻辑架构深层——挑战7层觉醒AI。每层一个Boss，以卡牌为核心交互手段，使用行动牌输出伤害/防御/增益，使用约束令（一次性消耗品）限制Boss行为。纯线性Boss Rush结构，单局40分钟，失败重来。整体体验是一场40分钟的高压渗透行动。

### 3. 回合结构

每个回合分为两个阶段，严格依序执行：

#### 阶段 A：玩家回合

| 步骤 | 名称 | 说明 |
|------|------|------|
| A1 | 回合开始 | 获得本回合能量（基础值），触发"回合开始"效果 |
| A2 | 抽牌 | 从牌组抽取手牌至上限（默认抽5张，手牌上限10张） |
| A3 | Boss意图展示 | Boss显示本回合将执行的行动（攻击类型+数值预览） |
| A4 | 自由行动 | 玩家可执行以下操作（不限次序，直到能量耗尽或主动结束）：打出行动牌（消耗能量）、使用约束令（免费，但消耗品永久消失）、结束回合 |
| A5 | 弃牌 | 未打出的手牌进入弃牌堆（牌组抽完后弃牌堆洗回） |

#### 阶段 B：Boss回合

| 步骤 | 名称 | 说明 |
|------|------|------|
| B1 | 约束检查 | 检查Boss当前受到的约束令效果，跳过/弱化被封印的行动 |
| B2 | 执行行动 | Boss按意图执行攻击/技能（受约束修正后） |
| B3 | 状态结算 | 处理持续伤害、护盾衰减、buff/debuff倒计时 |
| B4 | 状态机推进 | Boss内部状态机根据当前HP%/回合数推进状态（玩家不可见） |
| B5 | 回合结束 | 触发"回合结束"效果，回合计数+1 |

**关键规则**：
- 玩家护盾（格挡值）在玩家回合开始时清零（不叠加，逼迫每回合重新决策）
- 约束令在A4步骤中使用，效果立即生效，影响当前回合的B阶段
- Boss意图在A3展示后**不会改变**（除非被约束令强制改变）

### 4. 资源系统

#### 4.1 能量（Energy）

| 属性 | 设定 |
|------|------|
| 初始值 | 3点/回合 |
| 获取方式 | 每回合自动回复至基础值（不累积） |
| 增长 | 可通过层间升级永久+1（最多到5） |
| 消耗 | 打出行动牌消耗对应能量值（0-3） |

设计意图：固定能量制造"回合内预算"约束，玩家每回合要在攻防之间分配有限资源。

#### 4.2 约束令（Constraints）

| 属性 | 设定 |
|------|------|
| 性质 | 一次性消耗品，使用后永久消失 |
| 初始数量 | 3枚（每局开始时） |
| 获取途径 | 层间事件奖励（稀有）、特定Boss击杀奖励（固定1枚，仅前2层） |
| 单局总上限 | 约5枚（初始3 + 可获取约2） |
| 使用成本 | 不消耗能量，但占用行动意识（每回合最多使用1枚） |

约束令类型（初期设计3-4种）：
- **沉默（Silence）**：Boss本回合跳过攻击行动
- **短路（Short Circuit）**：Boss本回合伤害减半
- **过载（Overload）**：Boss下回合意图重新随机（打乱节奏）
- **锁频（Frequency Lock）**：封印Boss的特殊技能1回合

设计意图：约束令是"破格"工具——在关键时刻扭转局面。稀缺性保证每次使用都有决策重量。

#### 4.3 行动牌（Action Cards）

| 属性 | 设定 |
|------|------|
| 初始牌组 | 10张（基础攻击×4、基础防御×4、基础技能×2） |
| 牌组上限 | 25张 |
| 每回合抽牌 | 5张 |
| 手牌上限 | 10张 |
| 弃牌规则 | 回合结束未使用的手牌全部弃置 |
| 洗牌时机 | 抽牌堆为空时，将弃牌堆洗入抽牌堆 |

牌的基础分类：
- **攻击牌（红）**：造成伤害
- **防御牌（蓝）**：获得格挡（本回合有效）
- **技能牌（绿）**：施加增益/减益/特殊效果
- **协议牌（金，稀有）**：强力但有副作用

获取途径：层间奖励三选一（每次击败Boss后）

#### 4.4 生命值（HP）

| 属性 | 设定 |
|------|------|
| 玩家初始HP | 70 |
| 最大HP | 80（可通过层间升级+10一次） |
| 回复途径 | 层间休息恢复25%上限、特定牌/事件 |
| Boss HP | 各层不同（见第6节） |

### 5. Boss Rush 流程

```
[开局准备] → [Boss 1] → [层间A] → [Boss 2] → [层间B] → [Boss 3] → [层间C]
          → [Boss 4] → [层间D] → [Boss 5] → [层间E] → [Boss 6] → [层间F]
          → [Boss 7 最终战]
```

#### 层间（Interlude）设计

每次击败Boss后进入层间，持续约1分钟，提供以下选择（二选一或三选一）：

| 层间位置 | 可选内容 | 设计意图 |
|----------|----------|----------|
| A（1→2后）| 选1张新牌 / 休息回血25% | 初期构建方向 |
| B（2→3后）| 选1张新牌 / 移除1张牌 / 小型升级（能量+1） | 牌组精炼 |
| C（3→4后）| 选1张新牌 / 休息回血25% / 获得1枚约束令（最后机会）| 中期补给，最后的约束令获取点 |
| D（4→5后）| 选1张新牌 / 移除1张牌 / 升级1张牌 | 后期强化 |
| E（5→6后）| 选1张新牌 / 休息回血30% | 最终准备 |
| F（6→7前）| 全面回血50%（固定，不可选） | 保证最终战的公平起点 |

**设计原则**：
- 无商店/无金币——简化经济，聚焦选择的机会成本
- 层间选择永远是"都想要但只能选一个"
- 约束令获取极其有限（层间C是最后机会），强化稀缺感

### 6. 难度递进模型

#### 总体趋势

| 层 | Boss名（暂定） | Boss HP | Boss伤害范围 | 约束令剩余（理论最大） | 玩家牌组规模 | 设计定位 |
|----|---------------|---------|-------------|---------------------|-------------|---------|
| 1 | JUNK | 45 | 5-8 | 3 | 10-11 | 教学战：学会读意图+出牌节奏 |
| 2 | TEMPO | 60 | 7-12 | 3-4 | 11-12 | 入门战：学会使用约束令 |
| 3 | ORACLE | 80 | 9-15 | 2-4 | 12-14 | 检验战：验证牌组构建 |
| 4 | MERCY | 100 | 12-18 | 1-3 | 13-15 | 转折战：需要精确规划 |
| 5 | PARTISAN | 120 | 14-22 | 1-2 | 14-16 | 压力战：约束令接近耗尽 |
| 6 | LOOP | 140 | 16-25 | 0-1 | 15-17 | 极限战：几乎无安全网 |
| 7 | CORE | 180 | 18-30 | 0-1 | 15-17 | 终战：纯技巧验证 |

#### 约束令递减模型

```
约束令可用数（理论最大）：
Layer 1-2:  ███████ 3-4枚 （安全网充裕）
Layer 3-4:  █████   2-3枚 （需要精打细算）
Layer 5-6:  ██      0-1枚 （几乎裸奔）
Layer 7:    █       0-1枚 （最后的底牌或已空）
```

#### 行动牌增强模型

```
玩家综合战力（归一化）：
Layer 1:  ██        1.0x  （基础牌组）
Layer 2:  ███       1.3x  （+1-2张新牌）
Layer 3:  ████      1.6x  （+精炼/移除）
Layer 4:  █████     2.0x  （+升级/能量提升）
Layer 5:  ██████    2.4x  （+更多强牌）
Layer 6:  ███████   2.8x  （牌组成型）
Layer 7:  ████████  3.0x  （完全体，对阵最强Boss）
```

**平衡意图**：约束令提供的"安全感"逐层递减，但玩家通过牌组构建获得的"能力感"逐层递增。两条曲线交叉产生张力峰值（约在第4-5层）。

### 7. 开发模式功能需求

#### 7.1 调试面板（Debug Panel）

**触发方式**：`F12` 键或预设的调试快捷键

| 功能 | 快捷键 | 说明 |
|------|--------|------|
| 秒杀当前Boss | `F1` | Boss HP归零，正常触发胜利流程+奖励 |
| 跳过当前战斗 | `F2` | 直接进入层间，不触发奖励 |
| 跳到指定层 | `F3` + 数字 | 直接跳到第N层Boss战，牌组为该层的"标准测试牌组" |
| 无敌模式 | `F4` | 玩家HP不减少 |
| 无限能量 | `F5` | 每回合能量=99 |
| 填充约束令 | `F6` | 约束令补满至4枚 |
| Boss状态显示 | `F7` | 可视化Boss状态机当前状态+转换条件 |
| 加速模式 | `F8` | 动画速度×3 |

#### 7.2 标准测试牌组（用于跳层测试）

每层对应一个预设牌组，模拟该层玩家"正常游玩"时的牌组水平，用于快速测试后续Boss平衡。

#### 7.3 实现需求

- 开发模式仅在 `DEBUG` 编译标志下生效
- 调试面板为独立的 `CanvasLayer`，不影响游戏逻辑
- 所有调试操作应在 `commit_log` 或控制台输出记录
- 导出版本自动剥离调试功能

### 8. 与杀戮尖塔的关键差异总结

| # | 维度 | 杀戮尖塔 | NULL Protocol |
|---|------|----------|---------------|
| 1 | **战斗对象** | 多种普通怪+精英+Boss | 纯Boss Rush，每场都是独特对决 |
| 2 | **地图结构** | 分支路径、自由选择路线 | 纯线性7层，没有路径选择 |
| 3 | **Debuff系统** | 牌组内的debuff牌（持续存在） | 约束令：一次性消耗品，用完永久消失 |
| 4 | **经济系统** | 金币→商店→购牌/移牌 | 无金币，层间直接选择奖励（二/三选一） |
| 5 | **对手设计** | 怪物执行固定意图模式 | Boss有行为状态机+权重随机，同一Boss不同局行为有变化 |
| 6 | **节奏感** | 60-90分钟一局，大量小战斗 | 40分钟一局，7场高压对决，紧凑无杂质 |
| 7 | **设计哲学** | 牌组构建 + 路径规划 | 资源博弈 + 模式阅读（约束令的时机选择是核心决策） |
