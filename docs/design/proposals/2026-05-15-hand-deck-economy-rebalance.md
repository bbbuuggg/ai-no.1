## 1. 设计目标（MDA 反推）

### 目标美学
1. **Challenge**（主）：能量 6 点 vs 4 槽，每回合都有"哪张牌该让位"的紧张取舍
2. **Submission**（主）：BP 暗出对决的博弈快感（已由 BP 方案 B' 提供）
3. **Discovery**（副）：手牌池跨回合规划 → 玩家发现"留牌等能量"的策略

### 服务的 SDT 核心需求
- **Autonomy**：6 张手牌池 → 投入 4 张 → 4 槽 Pick，**三阶选择**
- **Competence**：1 费 / 2 费效果数值有明显梯度（详见第 5 节卡表）
- **Relatedness**：元素叙事（火焰/水流/根系）+ 双方对称牌库 → "镜像对决"主题感

### 与 BP 闭环的兼容承诺
- ✅ 不动 6 阶段状态机
- ✅ 不动 4 槽交替 Pick / 翻盅 / 结算 / 克制
- ⚠️ 候选生成：从"洗牌抽 4"改为"从手牌池投入 4"
- ⚠️ 部分翻案 Q-BP-4（0 费回归，形态变更为"灵感/调度"，不进 4 槽）
- ⚠️ 删除"预读"类 0 费牌（明牌模式无意义，未来做别的功能补回）

## 2. 推荐方案：手牌池模型（A2 + 抽牌保底）

### 2.1 核心机制

```
回合开始
  ├─ 从牌库抽牌补满手牌池（目标 6 张）
  ├─ ★抽牌保底校验★：若手牌池中 1 费牌 < 2 张 → 触发保底回退（见 2.2）
  ├─ 玩家从手牌池"投入 4 张"作为候选（玩家选 → Boss 用规则 AI 选）
  └─ 0 费过牌牌：可在投入候选**之前**或 Pick **之间**点击使用（≤2 次/回合）

Pick 阶段
  ├─ 4 槽交替 Pick（玩家先 / Boss 先 由先手机制定）
  └─ 候选 4 张全部进入 4 槽（cost 不够则强制空槽）

回合末
  ├─ 被 Pick 的 ≤4 张 → 弃牌堆
  ├─ 未投入候选的 2 张 → 留在手牌池
  └─ 0 费牌使用记录清零
```

### 2.2 抽牌保底算法（关键！）

```pseudocode
function refill_hand_pool(deck, hand_pool, target=6):
    # 第一步：常规抽牌补满
    while hand_pool.size < target and deck.not_empty:
        hand_pool.append(deck.draw())

    # 第二步：1 费保底校验
    one_cost_in_hand = count(c -> c.cost == 1, hand_pool)
    if one_cost_in_hand >= 2:
        return  # 直接通过

    # 第三步：保底回退
    needed = 2 - one_cost_in_hand
    one_cost_in_deck = filter(c -> c.cost == 1, deck)

    if one_cost_in_deck.size >= needed:
        # 替换：从手牌池移除 N 张非 1 费牌（优先移除 2 费），
        # 把它们丢进牌库底部，从牌库抽 N 张 1 费牌
        non_one_cost = filter(c -> c.cost != 1, hand_pool)
        for i in range(needed):
            removed = non_one_cost.pop_highest_cost()  # 优先移除 2 费
            hand_pool.remove(removed)
            deck.append_to_bottom(removed)
            hand_pool.append(one_cost_in_deck.pop_random())
    else:
        # 极端兜底：整个牌库 1 费 < needed，让步
        # 从弃牌堆里捞 1 费补（不洗回牌库，仅本次借用）
        # 仍不足 → 接受现状，UI 提示"⚠ 1费不足，本回合可能空槽"
        ...
```

**为什么必须保底**：base_energy=6 下若手牌池 6 张全 2 费 → 投入 4 张候选必有 2 张超能量 → 强制 2 槽空 → 玩家被 4 槽倍率系数稀释 → 体验灾难。

### 2.3 1 费张数概率证明（超几何分布）

牌库 15 张，抽 6 张到手牌池。设牌库 1 费牌共 K 张，抽到 ≥2 张 1 费的概率：

P(X≥2) = 1 - P(X=0) - P(X=1)
- P(X=0) = C(15-K,6) / C(15,6)
- P(X=1) = K · C(15-K,5) / C(15,6)
- C(15,6) = 5005

| K（牌库 1 费张数） | P(X=0) | P(X=1) | **P(X≥2)** |
|--------------------|--------|--------|-------------|
| 5 | 4.2% | 25.2% | 70.6% |
| 6 | 1.68% | 15.1% | 83.2% |
| **7** ⭐ | **0.56%** | **7.83%** | **91.6%** |
| 8 | 0.14% | 3.36% | 96.5% |

**结论**：K=7（牌库中 7 张 1 费牌）是甜蜜点 → 自然抽到 ≥2 张 1 费的概率 91.6%，剩余 8.4% 由保底算法 100% 兜住。

## 3. 推荐方案：0 费过牌牌（B2 删预读版）

### 3.1 设计原则
- **不占 4 槽**：点击 → 立即生效 → 不参与 BP 候选/翻盅
- **每回合上限 2 次**：防止刷爆牌库导致 LLM 信息过载
- **类型限定**：仅"调度类"+"灵感类"，**全部不再有"预读类"**（明牌博弈无意义）
- **位置**：UI 上单独一栏，与 4 槽分离

### 3.2 具体 3 张 0 费过牌牌

| ID | 名称 | 类型 | 效果 | 视觉关键词 |
|----|------|------|------|------------|
| `prep_insight` | **灵感涌动** | 灵感 | 立即从牌库抽 1 张到手牌池（手牌池超过 6 张时该牌作废，但消耗仍记 1 次） | 蓝色光弧从牌库飞入手牌区 |
| `prep_reorganize` | **重组协议** | 调度 | 从手牌池选 1 张丢入弃牌堆，从牌库抽 1 张回手牌池 | 卡牌粒子化 → 重新凝聚 |
| `prep_resonance` | **共振回路** | 调度 | 牌库洗牌（弃牌堆全部混入牌库重洗） | 牌库整体闪烁同步脉冲 |

**为什么这 3 张不破坏对称性**：
- 都是**操作自己的牌库/手牌池**，对 Boss 状态零影响
- Boss 也持有相同 3 张（牌库统一），双方都可以用
- LLM Boss 在自己的回合也会用规则 AI 触发这些过牌牌（v0.7.x 简化版）

### 3.3 LLM 信息同步契约（v0.2 修订：全明牌博弈版）

**用户最终决议（2026-05-15）**：当前 BP 模式是**全明牌博弈**——双方候选 4 张明牌、手牌池 6 张互相可见、抽到的 0 费内容互相可见、deck 分布也互相可见。**没有任何隐藏信息**。

**v0.5+ 老契约（已废弃）**：旧版"Boss 看不到玩家手牌内容 / 玩家看不到 Boss 手牌内容"是为传统暗出 + 陷阱模式设计的。BP 全明牌模式下这条契约**整体失效**。

**v0.7.x 新契约（完全公开 / 对称）**：

| 字段 | 玩家可见（B 浮层 / 全屏 UI） | Boss 可见（perception） |
|------|----|----|
| 对方手牌池**完整内容**（id + cost + 效果） | ✅ `boss.hand_pool` 全列表 | ✅ `player.hand_pool` 全列表 |
| 对方候选 4 张 | ✅ 已经显示 | ✅ `player_candidates` 已发送 |
| 对方牌库**类型分布**（atk/def/skl 计数） | ✅ 全屏 deck 视图 | ✅ `player.deck_type_counts` |
| 对方牌库**剩余具体牌**（id 列表） | ✅ 全屏 deck 视图 | ✅ `player.deck_cards` |
| 对方弃牌堆 | ✅ 全屏 discard 视图 | ✅ `player.discard_cards` |
| 对方本回合 0 费使用次数 / 用了哪张 | ✅ B 浮层 0 费日志 | ✅ `player.zerocost_used_log` |
| 对方 HP / Armor / Energy / 状态 | ✅ 已有 | ✅ 已有 |

**博弈深度从何而来**（既然全明牌）？

1. **BP 智力博弈**：4 槽 Pick 顺序 + 翻盅同步翻 → 双方在已知信息下做最优 Pick（类似国际象棋而非德扑）
2. **能量约束**：6 能量打 4 张 ≠ 任意组合，要选哪 4 张投入候选 = 战术决策
3. **0 费时机**：何时打灵感涌动 / 重组协议 / 共振回路 = 节奏决策
4. **元素克制 + 三角组合**：明牌下知道对方有什么不等于知道对方会怎么 Pick——Pick 顺序由先手随机决定
5. **LLM 长期模式识别**：Boss 能从历史回合推断玩家"风格"（激进/防守/经济流），但全明牌下这是合法博弈优势而非信息不对称

**结论**：v0.7.x 是**完全信息博弈**（perfect information game）——博弈深度来自决策空间复杂度，而非信息封闭。这是设计上的根本转向，类比从"德州扑克"改成"国际象棋"。

### 3.4 Boss 端 0 费使用策略（v0.2 新增）

因为双方对称持有 3 张 0 费，Boss 也需要决策何时用——v0.7.x 阶段用**规则 AI**（不消耗 LLM token）：

| 触发条件 | 使用的 0 费牌 |
|---------|-------------|
| 手牌池中 1 费牌 ≤ 1 张 且 候选投入前 | **灵感涌动**（抽 1） |
| 手牌池中存在死牌（克制色为对手主色 0 张时该色攻牌成废牌） | **重组协议**（弃 1 抽 1） |
| 手牌池中 ≥3 张 2 费且当前能量 ≤2 | **共振回路**（洗牌） |
| 已用 2 次/回合 | 不再使用（上限） |

**未来扩展**：v0.8+ Roguelike 阶段升级为 LLM 决策（Boss 也走 SYSTEM_PROMPT 决定 0 费时机），但当前阶段规则 AI 足够。

**全明牌补充说明**：玩家用 0 费的具体内容（哪张/抽到什么）会**完整**传给 Boss perception，因此 Boss 规则 AI 可以基于"玩家刚抽了 1 张水系 1 费"做反应（如手动改投候选组合）。这是合法策略，不是信息泄漏。

## 4. 推荐方案：经济（base_energy = 6）

### 4.1 能量预算表

每回合 6 能量，4 槽各放 1 张候选，cost 分布与剩余/超支：

| 候选 cost 分布 | 总耗 | 余/超 | 体验 |
|----------------|------|-------|------|
| 4×1费 | 4 | +2（多 2） | 太省 → 用过牌牌补充节奏 |
| 3×1费 + 1×2费 | 5 | +1（多 1） | 理想节奏 |
| **2×1费 + 2×2费** | **6** | **0（刚好）** | **甜蜜点：紧绷取舍** |
| 1×1费 + 3×2费 | 7 | -1（缺 1） | **必须留空 1 槽 或 用过牌牌救场** |
| 4×2费 | 8 | -2（缺 2） | 必须留空 2 槽 → 倍率劣势 |

**设计意图**：玩家**永远在"想全打 2 费但能量不够"vs"用 1 费补缺口"之间挣扎** → Challenge 美学拉满。

### 4.2 牌库 cost 分布（统一 15 张）

| cost | 张数 | 占比 |
|------|------|------|
| 0 费（过牌） | 3 | 20% |
| **1 费（核心）** | **7** ⭐ | **47%** |
| 2 费（高效） | 5 | 33% |

**为何 1 费占 47%**：满足第 2.3 节超几何概率 K=7 → 抽到 ≥2 张 1 费概率 91.6% + 保底兜底 = 100%。

### 5.3 对称牌库 + 全明牌的退化风险

**风险**：双方完全镜像 + 信息完全公开 → 是否会陷入"互相猜对方出什么"的元博弈僵局或决定论？

**评估**：
- BP 模式是**完全信息博弈**（类比国际象棋）——双方手牌池/牌库/弃牌堆/0费用法**全部公开**
- 决定论问题：理论上存在唯一最优 Pick → 但 4! × 4! × 元素克制矩阵 × 3 类0费时机 = 决策空间足够大，LLM 与人类都不会算到最优
- 双方非对称的是**计算资源**：
  - LLM Boss 优势：长期模式识别 + 完整历史回放
  - 玩家优势：直觉、心流、跨回合记忆压力小（不需要每回合从 0 算）
- v0.7.x 接受对称作为**博弈纯度测试床**——验证"全明牌 + 对称牌库"是否真的能产生有趣对局
- v0.8+ Roguelike 引入卡组构筑后双方牌库自然分化，自动消解此风险

**playtest 验收信号**：
- ✅ 健康：30 局中 ≥70% 对局有 ≥2 个"令人意外的 Pick 决策"（玩家事后觉得"原来还能这样玩"）
- ❌ 退化：连续 5 局都是同一种 Pick 模板（如"先手永远投攻+攻+攻+防"）→ 牌库设计失败，需重做

**结论**：v0.7.x 接受对称 + 全明牌，作为博弈纯度测试床。如 playtest 显示退化，v0.7.1 再加随机扰动（如每回合随机封禁 1 张牌）。

## 6. 推荐方案：HP + 枯竭（4-5 回合目标）

### 6.1 HP 反推数学

**单回合期望净伤害估算**：
- 牌库平均攻击牌伤害 ≈ 5（`c_pulse`=5、`c_emberflare`=4、`c_pyreburn`=9、`c_solarblaze`=6、`c_thornveil`=5、`c_briarbind`=7、`c_eroderoot`=4 → 平均 5.7，扣除护甲折损 ≈ 5）
- 4 槽中通常 1.5 张是攻击牌（其余防御/技能/0费）
- 元素克制：1/3 概率 ×1.5、1/3 概率 ×1.0、1/3 概率 ×0.5 → **期望系数 1.0**
- **单方期望输出**：1.5 × 5 × 1.0 = **7.5 伤害/回合**
- 对方防御牌（≈30% 候选是防御）格挡掉 ≈30% → **实际净伤害 ≈ 5.25/回合**

**HP 反推**：
- 目标 4-5 回合结束 → 总伤害 21-26
- **推荐 HP = 25（双方相同）** → 4.76 回合命中目标 ✓

### 6.2 枯竭曲线（压低后版本）

**触发**：第 6 回合开始（正常节奏 4-5 回合内已结束，第 6 回合是异常拖局信号）

| 回合 | 双方扣血 | 累计扣血 |
|------|----------|----------|
| 6 | 3 | 3 |
| 7 | 5 | 8 |
| 8 | 7 | 15 |
| 9 | 10 | 25 |
| 10 | 14 | 39 |

**指数递增**：保证最迟第 9 回合双方 HP 必清零（25 - 25 = 0），强制结束。

**实现**：在 `BlindClashBattle._round_start` 中，若 `_current_round >= 6` 则双方各扣 `[0,0,0,0,0,3,5,7,10,14][min(round,9)]` 血。

### 6.3 体验保护

- 第 5 回合 UI 显示警告："⚠ 下回合起进入【枯竭】"
- 第 6 回合 UI 全屏闪烁红雾："【枯竭】协议生效"
- 战斗日志详细记录枯竭扣血来源（与卡牌伤害区分开）
